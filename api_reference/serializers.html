Serialization and Reflection

Headers in ouly/serializers/ and ouly/reflection/. ouly::read and ouly::write (ouly/serializers/serializers.hpp) are overloaded for binary and structured streams; ouly::bind (ouly/reflection/bind.hpp) builds reflection declarations.

See Serialization Tutorial for a guided introduction.

template<typename Config = ouly::config<>, std::endian Endian = std::endian::little>
class stream_type_registry : public ouly::detail::runtime_type_reader_base, public ouly::detail::runtime_type_writer_base<ouly::config<>>, public ouly::detail::binary_any_reader_base<std::endian::little>, public ouly::detail::binary_any_writer_base<std::endian::little>

Registry resolving stream type ids to concrete C++ types for runtime_type and any (de)serialization.

Each bound type contributes a read trampoline (construct the type into the runtime_type’s value storage and return a parse context) and a write trampoline (emit the stored value). Both are fully type-erased behind this registry so the parser/writer stay decoupled from the concrete bound types.

A runtime_type is serialized just like a std::variant, as a two-field object: 

field:
  type: 1        # the ouly::type_id
  value: ...     # parsed/emitted as the bound concrete type

Field names (“type” / “value”) are configurable through the same mechanism as variant: they are run through the Config’s string transform (transform_t<Config>). Choosing a Config with a string transform therefore renames these keys (along with every other key in the document). For example, with 

using upper = ouly::config<ouly::to_upper>;
ouly::stream_type_registry<upper> reg; // emits/parses TYPE: and VALUE:
the keys become “TYPE” and “VALUE”. The Config used here must match the one passed to from_string/to_string (it is deduced from this registry’s template parameter).

Template Parameters:

Config – The serialization configuration (must match the from_string/to_string call).

Public Functions

inline void set_name_resolver(std::function<ouly::type_id(std::string_view)> from_name, std::function<std::string_view(ouly::type_id)> to_name)

Installs name<->type_id resolvers used to (de)serialize the “type” scalar as a string name instead of an integer.

When set, the serializers route the “type” field through these functors. When left unset, the default path is used (a convert<type_id> specialization if present, otherwise a plain integer). The view returned by to_name must outlive the serialization call (e.g. a string literal or a string owned by the caller).
