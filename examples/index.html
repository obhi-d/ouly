Examples

The unit tests in unit_tests/ are OULY’s most complete set of examples: every component is exercised there, and the tests are built and run by CI on every supported compiler, so they always match the current API. The tutorials (Tutorials) are the place to start; the tests show edge cases and less common features.

  • Unit Test Examples
    • Scheduler: continuations
    • Scheduler: scoped joins
    • auto_parallel_for: range splitting
    • small_vector: storage mode
    • coalescing_arena_allocator: retained arenas
    • Memory-mapped file ranges
    • ECS: collections
    • microexpr: operators and identifiers

Building and running the tests

cmake --preset=linux-default            # or macos-default / windows-test
cmake --build build/linux-default
ctest --test-dir build/linux-default --output-on-failure

# One executable per test target, named test_<name> (see unit_tests/CMakeLists.txt)
ctest --test-dir build/linux-default -R scheduler
./build/linux-default/unit_tests/test_small_vector "[capacity]"   # Catch2 tag filter

Adding an example

New usage examples belong in the unit tests, where CI keeps them compiling. Add a TEST_CASE to the matching file, or a new file registered with add_unit_test(NAME ... FILES ...) in unit_tests/CMakeLists.txt; see Contributing.
